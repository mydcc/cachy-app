# Documentation defects in Bitunix's own reference

Crawled on: 2026-09-28. Re-audited against the live vendor pages 2026-09-28.

A quarantine, kept out of the endpoint files on purpose. A vendor typo is not a
finding about Cachy, and mixing the two makes both harder to trust. Per-group
lists live in the group files and are indexed at the bottom.

## The headline finding of the audit: the mirror is usually right

A defect-hunting pass over the whole set produced a list of ~20 suspected
errors. When each was checked against the live vendor page, **the large
majority turned out to be faithful transcriptions of a defective vendor page**,
not mirror errors. That distinction matters: correcting those would have made
the mirror *less* accurate, and would have propagated the vendor's bugs into a
document whose whole value is that it can be diffed against its source.

The set was then checked the other way, for text that has **no vendor source at
all** — and that search found a real problem. See the next section.

## ⚠️ Text that had no vendor source

One passage was not a transcription error. It was **invented**, and it had
propagated into three files before this audit.

`01_sign.md` described the `nonce` parameter as a
**"32-char hex string (128-bit random)"**.

- The vendor writes `Random string，32bits` on the signature page and
  `random string, 32-bit, generated by the caller` on the introduction page.
- **No Bitunix page says "hex". None says "128-bit". None says "32-char".**
- The phrase is also self-contradictory: 128 bits is 32 hex *digits*, not 32
  characters.
- Bitunix's own samples contradict all of it — the REST signing samples use a
  six-character nonce (`"123456"`), and the WebSocket login example uses a
  32-character alphanumeric one.

The likely origin: someone counted characters in the 32-character WebSocket
sample and back-derived a bit-width from it. Now corrected in all three
locations, with the vendor's actual wording and a note on what remains
genuinely unknown (the charset, and any real length requirement).

**This is the failure mode this file exists to prevent.** An invented sentence
in a reference is worse than a missing one, because a missing one is visible
and an invented one is trusted.

## ⚠️ Bitunix's two pages disagree on the WebSocket prehash

Unresolved, and it is a signing-path contradiction.

| Source | Formula |
|---|---|
| `common/sign.html` | `SHA256(nonce + timestamp + apiKey + params)` — `params` **included** |
| `websocket/prepare/WebSocket.html`, Go sample | `sha256Hash(fmt.Sprintf("%s%d%s", nonce, timestamp, apiKey))` — `params` **omitted** |
| `websocket/prepare/WebSocket.html`, Python sample | `sha256Hash(nonce + str(timestamp) + api_key)` — `params` **omitted** |

Both code samples on the WebSocket page hash only three values. One of the two
pages is wrong and the docs do not say which. This mirror carries **both**
versions — the `params`-inclusive one in `01_sign.md`, the omitting one in
`08_websocket.md` where the WebSocket page's samples were transcribed. A reader
implementing from `08_websocket.md` alone will produce signatures that
`01_sign.md` contradicts.

## ⚠️ Bitunix's two pages disagree on the WebSocket timestamp unit

| Source | Says |
|---|---|
| WebSocket connect page, Login table | `Seconds format of Unix timestamp` |
| WebSocket connect page, Go sample | `time.Now().Unix()` — seconds |
| WebSocket connect page, Python sample | `int(time.time()) — seconds |
| WebSocket connect page, JSON example | `"timestamp": 1747402389` — 10 digits, seconds |
| The example string on the **signature** page | `timestamp1724285700000` — **13 digits, milliseconds** |

Seconds is the better-supported reading — four independent sources on the
dedicated page against one example on the shared page — and is the one the
REST/WS split implies. Recorded rather than silently normalised.

## ⚠️ Two private channel names: code and vendor disagree, nothing settles it

The most consequential finding, because it is a live-code question rather than
a documentation one.

| Channel | Vendor's `ch` value | This mirror | Cachy subscribes with |
|---|---|---|---|
| Balance | **`balance`** | `wallet` | `wallet` |
| TP/SL | **`tpsl`** | `tp_sl` | `tp_sl` |

The vendor states each name twice — in the Description and again in the `ch` row
— and both statements agree. The code and the mirror agree with each other and
disagree with the vendor, and **nothing corroborates either side**:

- The comment justifying `tp_sl`'s use in `subscribePrivate`
  ([bitunixWs.ts](../../src/services/bitunixWs.ts)) cites **this documentation
  set** as its source. That is circular: the code and the mirror cannot both be
  evidence for each other.
- The channel list carries no citation at all.
- The vendor's WebSocket connect page publishes no authoritative list of private
  channel names, so there is no third source to break the tie.

If the vendor is right, both subscribes are rejected and **no balance update and
no TP/SL update ever arrives** — silently, because a rejected subscription is a
push that does not come. A client treating the socket as the live balance source
would show a stale figure indefinitely, and a trader would see a stop they
believe is managed disappear from the display.

**This needs a credentialed check against the live gateway. Documentation
cannot settle it.** Recorded in `08_websocket.md` at both channels.

## ⚠️ The mirror repairs vendor bugs silently, in both directions

The deeper structural problem, and the one that produced the invented nonce
text. Some entries in this set are not verbatim, and nothing in the files marks
which.

**Repairs that improved the mirror, undeclared:**

| File | Vendor | Mirror | Nature |
|---|---|---|---|
| `05_position.md` | `endTime` described as *"Start timestamp(position create time)"* | "End timestamp" | Vendor copy-paste bug; the vendor's own example value is later than `startTime`, confirming end semantics |
| `05_position.md` | `subAccountId` described as *"With **subAccountUid**…"* | `subAccountId` | Vendor names a field that does not exist |
| `07_trade.md` | Same two, plus `tpStopType`/`slStopType` example values of `"MARK"`, which is **not in the documented enum** `MARK_PRICE`/`LAST_PRICE` | corrected to `MARK_PRICE` | The most consequential: the mirror rewrote example data |
| `08_websocket.md` | unsubscribe example uses `"channel"` where the parameter table specifies `ch` | `ch` | Correct call |
| `07_trade.md` | garbled `limit` prose on the depth page | one clean sentence | Readability |

**Repairs that damaged the mirror, undeclared — now fixed:**

| File | Vendor | Was | Nature |
|---|---|---|---|
| `04_market.md` | `open`/`high`/`low`/`close` typed `string`, example quoted | typed `decimal`, example unquoted | **Would break code.** A `decimal.js` layer parsed a number where the API sends a string; a strict TS response type built from this rejected the real payload |
| `04_market.md` | `quoteVol` typed `string` | `decimal / string` | Same class |
| `04_market.md` | kline volumes described *"for the kline period"* | *"(last 24h)"* | A kline bar is a period, not 24 h |
| `08_websocket.md` | TP/SL `status` is `NEW`/`CANCELED`/`SYSTEM_CANCELED`/`FILLED`/`FAILED`, and the page **explicitly disclaims** `INIT`, `PENDING_CANCEL`, `TRIGGER_WAIT_PLACE` and says *"Do not document `PART_FILLED` on this channel"* | `INIT`, `NEW`, `PART_FILLED`, `CANCELED`, `FILLED` | Documented a status that cannot occur; omitted two that can, including `SYSTEM_CANCELED` — which is how a venue-initiated cancel is told from a user-initiated one |
| `08_websocket.md` | TP/SL quantities are *"Omitted if unused"* | *"At least one of `tpQty`/`slQty` is required"* | **Invented requirement.** Removed |

The policy this set should have followed, and now states in its front matter:
**transcribe verbatim, and mark every repair.** A reader who cannot tell which
text is the vendor's and which is Cachy's cannot trust either — and cannot tell
a repair from a second invention.

## Vendor defects transcribed faithfully, with a note in place

In each of these the mirror is correct and Bitunix is wrong. The note exists so
a future crawl does not "fix" the mirror back to the vendor's version.

| Topic | Where | The defect |
|---|---|---|
| `.index` notation vs nested arrays | `04_market.md` | The depth table says `asks.index[0]` is the ask price; the payload is `asks: [[price, amount], …]` with no `index` key. The table version is **unusable as written** — the real path is `data.asks[0][0]`. The REST `.index` has no counterpart in the WebSocket depth docs, which use `data.a`/`data.b`, so it is an isolated artifact |
| Verb in a path | `04_market.md` | `get_funding_rate_history` is the only verb path of seven market endpoints. **Must be transcribed as-is** — normalising it to `/funding_rate/history` returns 404 |
| Colliding page anchors | `04_market.md` | The single, batch and history funding-rate pages all carry the H1 *"Get Funding Rate"* and the anchor `#get-funding-rate`. Section names are not reliable cross-references |
| `starTime` | `04_market.md` | Genuinely spelled without the `t`, is a request-parameter name, and is unfixed. No working example of it exists anywhere — the page's `curl` never uses it |
| `defaultMarginMode` | `04_market.md` | Triply contradictory on one row: type column `string`, enum `Isolation`/`Cross`, example the unquoted integer `1`. A different page documents the same concept as `ISOLATION`/`CROSS`. **Three renderings across two pages, none authoritative** |
| Indistinguishable ticker volumes | `04_market.md` | On the tickers page `quoteVol` is *"of the coin"* and `baseVol` is *"of the last 24 hours"* — neither names a currency. The kline page is unambiguous; the tickers page is not |
| Placeholder sample data | `04_market.md` | Tickers: every volume `"0"` and all four OHLC fields `"6.31"` on both symbols against `markPrice` `57892.1` — a stock/ETF template. Depth: a spot-shaped book (~0.10) on a `BTCUSDT` request, requesting `limit=max` while showing 2 levels per side |
| Position Channel description | `08_websocket.md` | The three events listed are **order** events on the position page. Near-identical to the Order Channel's description, differing only in the channel name and a typo. The Push Parameters table is correctly position-specific and is *not* affected |
| Depth `ch` and `data` types | `08_websocket.md` | `ch` typed `Object` though the example sends `"depth_book1"`; `data` typed `String` though the example sends an object. `ch: Object` is the sole outlier — the other nine channels type it `String` |
| Trade `ts` type | `08_websocket.md` | Typed `String`, example sends an unquoted integer, and it is the only channel of ten that does this |
| Ticker example | `08_websocket.md` | Envelope `"symbol": "BNBUSDT"` against body `data.s: "BTCUSDT"`, and the same page's field table glosses `data.s` as *"E.g. ETHUSDT"* — a third symbol matching neither. Treat `data.s` as authoritative |
| Depth channel names | `08_websocket.md` | `books` is plural but `book1`, `book5`, `book15` are **singular**. Intentional-looking, and repeated in the vendor's own subscribe examples, so real names rather than typos |
| `starTime` / `endTime` Required column | `04_market.md` | The live Required cell literally reads `fasle` |
| Effect on `endTime`/`subAccountId` | `05_position.md` | Same copy-paste family as above |

## Error codes

`09_error_codes.md` holds the complete table — **76 codes, verified complete
against the vendor page with no additions and no omissions** — plus a
defects section covering the duplicated codes (`30034`/`30033`,
`30037`/`30036`), the systemic truncation from `30020` onward where every
description ends in a bare colon, the `30015` "Mini"/"Max" typo, and the
`30002`/`30003` pair that reads as swapped but may equally be an
under-documented two-direction rule.

There is **no Bitunix equivalent of Bitget's 983-code error enumeration** —
Bitunix publishes a small curated list and this mirror captured all of it.

## Unsupported vendor claims

- `30002` / `30003` reading as swapped — **unresolved**, and deliberately not
  resolved: a single liquidation price is violated from both directions, so the
  texts fit "swapped" and "both directions" equally well.
- `30015` "Mini" almost certainly meaning "Max" — inference from the
  neighbouring `30014`, not something the page says.
- The WebSocket prehash and timestamp unit — see above, unresolved.
- `entryValue` on pending positions is documented by the vendor as *"Available
  amount for positions"*, which its own example contradicts: `qty: 0.5`,
  `entryValue: 30000`, `margin: 300` at 100× leverage is position notional, not
  available margin. The mirror transcribes the vendor's wording; the wording is
  wrong. Note the page's `avgOpenPrice` is `"1.0"`, a stale placeholder, so the
  arithmetic has to be run against the history page's price to make sense at all.
- `liqQty` on **history** positions is documented as *"liquidate quantity"* —
  ambiguous English, almost certainly a machine translation. A closed position
  has no live liquidation quantity, and the vendor's example returns `"0"` for
  a profitably closed position, so the field is most likely the quantity
  liquidated. The vendor does not resolve its own ambiguity and neither does the
  mirror.

## Cachy-side divergences recorded here

Distinct from vendor defects: places where this set and Cachy's code disagree,
or where two files in this set contradict each other.

| Topic | State |
|---|---|
| `fundingRate` unit on the history endpoint | The batch endpoint's value is **a percentage** and is divided by 100 at ingestion — settled by `fetchBitunixFundingRates` in [`marketData.ts:759`](../../src/services/api/marketData.ts). The **history** endpoint is marked "already a fraction, do not divide" with **no code evidence**, because nothing in the repository reads `get_funding_rate_history`. `04_market.md` and `QUICK_REFERENCE.md` previously asserted the opposite of each other here; both now carry the same unresolved marking. A 100× error in a funding rate is invisible in a single reading |
| `queryCanceled` on `Get History Orders` | Audited and **correct** in the mirror. `true` returns cancelled orders only over the last 3 days; `false` excludes them over 90 days. The two branches are internally consistent |
| `available` formula on `Get Single Account` | The vendor states `available + crossUnrealizedPNL = actual maximum open amount`, omitting `isolationUnrealizedPNL` from the same response. The mirror transcribes it faithfully. The vendor's own example sets `isolationUnrealizedPNL` to `0`, so the example cannot confirm or refute it. **Unverified either way** |
| The plan-order family | Undocumented by the vendor — no `plan` section, 404 on the history page. See `INTEGRATION_STATUS.md` for what that means for Cachy |
| Signature path binding | Bitunix's prehash is `nonce + timestamp + apiKey + queryParams + body` and **excludes the request path and HTTP method**, so one signature is not bound to one endpoint |
