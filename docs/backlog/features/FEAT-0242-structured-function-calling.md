# FEAT-0242 — Replace regex-based JSON action parsing with structured function calling

## Problem

Trading actions (such as setting entry price, stop-loss, take-profit targets) are currently generated by instructing the LLM to output a markdown JSON codeblock at the end of its response. The client extracts these actions using a regular expression (`/```json\s*[\s\S]*?"action"[\s\S]*?```/g`).

This approach has multiple failure modes:
1. Slight variations in markdown fences or trailing commentary cause regex matching failures.
2. Incomplete or invalid JSON blocks leak into the user's visible chat text.
3. The model wastes output tokens formatting and indenting JSON strings instead of communicating with the trader.

## Proposal

Transition to provider-native Tool Use / Function Calling for supported providers (OpenAI, Anthropic, Gemini, OpenRouter):
1. Define a strongly typed tool schema (e.g. `applyTradeSetup` or discrete action tools) matching Cachy's supported trading parameters.
2. Pass tool definitions to the provider API and handle tool execution blocks separately from user message text.
3. Keep a resilient fallback JSON parser for local models (e.g. Ollama) that do not support native tool calling.

## Acceptance criteria

- [ ] OpenAI, Anthropic, and Gemini proxy routes support structured tool/function definitions.
- [ ] Actions executed via tool calls cleanly separate message commentary from structured parameter payloads.
- [ ] No raw action JSON codeblocks appear in the user-visible chat transcript when tool calling is enabled.
- [ ] Fallback parser continues to support providers without function calling support.

## Out of scope

- Direct execution of exchange orders without user interaction (orders still pass through Cachy's trade panel and verification flow).
